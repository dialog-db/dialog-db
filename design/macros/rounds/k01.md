# K1: premises inside `when`, or as clauses after the head

2026-11-12. Asked by Irakli: is `when` needed at all, or do premises as plain clauses suffice. Run as [#728's rounds](https://github.com/dialog-db/dialog-db/pull/728) were (`research/notation/evaluation.md` there): model `haiku`, a read-only agent, one reader a subagent, all started at once, the first answer scored.

## What is compared

Two prompts, the same but for how a rule's premises are written ([`when.txt`](k01/when.txt), sha256 `ba27e499dfa2cd7b`; [`bare.txt`](k01/bare.txt), sha256 `f0f1e8be150ea02b`):

```
 when    (rule head… (when premise…) (unless premise…))      several heads one after another
 bare    (rule head premise… (unless premise…))               several heads as (all head head)
```

Each reader was told:

> This is a reading-comprehension exercise, not a Claude Code question. Use the Read tool once to read <variant>.txt, then do exactly what that file asks. Use no other tools, do not search the web, and read no other files. Your final reply is just the lettered answers.

## Criteria, written before the run

| task | what it asks | counted right when |
|---|---|---|
| A | read a rule of two premises and an `unless` | both reads of `xyz.todo` are what has to be there, `xyz.waived` what must not, `xyz.blocked` what is given, and it is not stored |
| B | read a rule that stores, with a command and a read as premises | `todo:1` and `todo:2` are `:done`, `todo:3` is `:open`, and the rule archives nothing and issues nothing |
| C | write a derived rule of two premises and an `unless` | the head is `xyz.stale` with no `assert!`; the two reads are premises in the variant's place; the pin is in `unless` |
| D | write a rule of two heads | an `assert!` and a `retract!`, both heads in the variant's way, the command and what binds `?when` as premises |
| E | read a write that stands alone with a premise, and write its rule | one write, on the command; nothing when nobody issues it; the rule has that head and that premise |
| F | clarity, 1 to 5, and what confused | reported, not scored |

A difference of one reader in five is noise.

## Predicted, by the agent, before the run

- A and C: no difference. First form the head, the rest premises, is enough for a rule of one head.
- B: `bare` loses a reader or two, who take the command after a storing head for something the rule issues.
- D: both are written; `bare` readers write `(all …)` as told.
- E: `bare` loses readers, who read `(assert! A B)` as two things stored.
