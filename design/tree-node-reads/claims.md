# The tree reads nodes beside the capability system: claims

| claim | kind | backing | status |
|---|---|---|---|
| A tree operation reads nodes through an `Accessor`, which takes the node cache from the environment's `Holds` (`NodeCache::of(env, subject)`) and answers cached nodes itself | fact | `rust/dialog-search-tree/src/accessor.rs` on main `20f0a45` (`Accessor::new`, `load_node`) | holds |
| On a cache miss the tree performs `Load`, which returns the block's bytes (`Option<Buffer>`), then checks them against the hash, validates and decodes them | fact | `rust/dialog-effects/src/archive/load.rs` (`type Output = Result<Option<Buffer>, ArchiveError>`); `accessor.rs` `fetch_node`, `checked` | holds |
| `Holds` is a map of type-erased values under string keys, chosen by the code that puts a value in and takes it out | fact | `rust/dialog-common/src/holds.rs` | holds |
| The node cache is owned by the environment: one per space, released through the peer | fact | `rust/dialog-repository/src/repository/caches.rs`; `Peer::caches` in `rust/dialog-peer/src/peer.rs` | holds |
| #733 added a `NodeSource` kept through `Holds`, asked before every load; its lookup cost up to 16% more instructions than main on the perf scenarios, all of it formatting the key and looking it up | fact | `dialog-perf` sweep and callgrind diff, [research journal 2026-11-06](../../research/single-file-format/journal.md) | holds; mitigated by a lookup on miss only |
| `Holds` keeps more than the node cache: the formula cache, the repository's caches, the network's routes | fact | `held_key` users on main: `dialog-query/src/formula/cache.rs`, `dialog-repository/src/repository/caches.rs`, `dialog-network/src/routes.rs` | holds |
| The tree should ask for what it needs through the capability system, with no side channels; caching, reading and decoding belong to providers | opinion | the maintainer, 2026-11-07 | - |
| `dialog-storage` (where the `fs` archive lives) does not depend on `dialog-search-tree` | fact | `rust/dialog-storage/Cargo.toml` | holds; whether it *must not* is not yet asked |
| Reading nodes in place (rows) beats building a block on a miss, for cold reads and for the memory cached nodes take | hypothesis | measured once before the six-member bench (cold reads level with main only in place; rows nodes about a third of the memory). Confirmed if the six-member bench, cold reads and memory included, shows the same with both variants; refuted if building blocks on a miss is within the run-to-run spread | open |
| Code paths have ended up with caches of their own, reads have bypassed the cache, and environments have been introduced without one; the maintainer keeps fixing these | fact | the maintainer, 2026-11-07; main's history: #730 took the node cache out of trees and onto the store, #735 moved it onto the environment and removed `Nodes`/`Cached`, #637 bounded a per-branch cache, #742 made the environment bound every cache it holds | holds |
| An environment that keeps nothing gets no node cache, and the tree then reads uncached, with no error and nothing in the types to say so | fact | `NodeCache::of` returns `None` when `env.held` keeps nothing (`dialog-search-tree/src/cache/nodes.rs`); `Accessor::load_node` then fetches without a cache (`accessor.rs`); `notes/tree-reads-as-effects.md`: "an env that holds nothing (a bare store) has no cache" | holds |
| "A new read path cannot bypass the cache or the hydration policy, because it has no way to get a node except `Load` on the env" | hypothesis | `notes/tree-reads-as-effects.md`, Consequences. Holds for reads made through the tree's `Accessor`; `Load` itself returns uncached bytes, so code that performs `Load` and decodes bypasses the node cache. Refuted as stated if such a path exists in non-test code: push forwards remote blocks decoded and uncached, on purpose (`branch/push.rs`, `remote_block`) | refuted as stated; holds for reads through the tree |
| The node cache is filled from more than one place: the tree's `Accessor`, and the query session's `Load` provider, which decodes what it loads and inserts it | fact | `dialog-repository/src/repository/branch/session.rs` (the `ArchiveLoad` provider inserting into `cache`), `dialog-search-tree/src/accessor.rs` | holds |
| The environment's whole job is to be the cache and carry everything, so it can be passed around, evicted, and reused across sessions, with no implicit dependencies elsewhere | opinion | the maintainer, 2026-11-07: "there is the environment, it is a cache" | - |
| Outside the cache itself, code on main touches the node cache for three things: persist keeps the nodes it seals before they are flushed (and forgets them if the flush fails); the tree peeks at a node only if it is already in memory (`cached`, for a piece summary, with no IO); read-ahead warms siblings only where there is a cache to land in (`keeps`, `warm`) | fact | `dialog-search-tree/src/tree/transient.rs` (`persist`, `cached`), `hitchhiker.rs` (`persist`), `walker.rs` (`keeps`, `warm`); `notes/tree-reads-as-effects.md` | holds |
| Each of those is a way of asking for a node (made just now; only from memory; ahead of need), not a need to see the cache: an environment could answer each if the request said which | hypothesis | confirmed if every caller can be written against a node request carrying that policy with no reference to a cache; refuted by a caller that needs the cache itself (its size, its contents, its eviction) | open |
| Sync, push and serving a peer need a block's bytes, not a node and not the cache; push forwarding a remote's block wants it not kept | fact | `branch/push.rs` (`remote_block`, streamed through, "the local archive keeps none of it") | holds |
| Answering every node read by a capability on the environment costs more per read than today's lookup made once per operation and then a direct cache hit | hypothesis | today's cost of one held lookup per operation is small and fixed (#735's perf note); a per-read lookup measured up to 16% (the regression in this topic's description). Confirmed or refuted by `dialog-perf` instructions on read-point, rule-point and subscribe-fanout with a prototype | open |
| The tree's perspective is that it just needs to get a node; callers should not have to think about a cache | opinion | the maintainer, 2026-11-07, held tentatively ("I could be wrong") | - |
| The design is an object-capability model with effects: all I/O happens through effects, and the environment is their provider | opinion | the maintainer, 2026-11-07 (the intended design) | - |
| The search tree was written before the capability model, and its transition to it is partial | fact | `notes/tree-reads-as-effects.md`, Context: "The search tree was written before the capability model"; the cache and node source reached through `Holds` beside `Load` (this ledger, above) | holds |
| What a tree needs should be expressed as capabilities it invokes, which providers answer, so each concern sits with whoever owns it | opinion | the maintainer, 2026-11-07: "What is a tree's concern? We should have that expressed as capabilities so that it can invoke them and then provider provides them" | - |
| Code that is partway through the transition exists beyond the tree: the query engine's formula cache and the repository's caches are kept through `Holds` too | fact | `dialog-query/src/formula/cache.rs`, `dialog-repository/src/repository/caches.rs` on main | holds |
| On main a `PersistentNode`'s hash is computed from its own bytes, and its only constructor from a block validates the layout: no node can carry a hash its bytes do not have | fact | `dialog-search-tree/src/node/persistent.rs` on main (`hash()` is `self.buffer.blake3_hash()`; `TryFrom<Buffer>` checks the body); `dialog-common/src/buffer.rs` (`blake3_hash` memoized from the bytes) | holds |
| What a load still checks is that the node is the one asked for (its hash equals the request's), which needs no trust in whoever answered | fact | `accessor.rs` `checked` on main | holds |
| On #733 a node built from rows takes its hash from the store (`NodeRows::hash`), not from its content: the type does not hold the invariant there; the store does, by writing a frame only after checking it rebuilds the exact block | fact | `dialog-search-tree/src/node/persistent.rs` on the branch (`hash()` returns `rows.rows.hash()`); `NodeRows` is an `unsafe` trait; `dialog-archive-file` writes a frame only if it rebuilds the block | holds |
| A node's hash should be a type invariant, so the tree trusts no one: it receives a node type that cannot exist with a hash its content does not match | opinion | the maintainer, 2026-11-07; withdrawn by the maintainer the same day, see the next opinion | withdrawn |
| Holding the hash invariant by type for a node read in place costs encoding its block on every cache miss (the bytes the hash is over), which is the work reading in place avoids | hypothesis | follows from the hash being over the block's bytes; refuted if a hash can be computed from rows without encoding (it cannot for blake3 over the encoding, unless the encoding is streamed into the hasher, which still costs the encoding's CPU but not its allocation). Its cost is measurable on the six-member bench's cold reads | open |
| A node read from rows can be hashed without decoding it, by streaming its bytes into the hasher | opinion, then fact | the maintainer, 2026-11-07. Holds with one correction: a block's bytes are the tree's encoding of the node (columns, front-coded keys, varints), not its tokens end to end (`NodeRows::block`: "built by the tree's encoder"), so streaming them means running the encoder into the hasher: no decoding and no allocation, but the encoder's work | holds, as corrected |
| Hashing a rows node by streaming its encoding into the hasher, once on a cache miss, costs little next to the rest of a cold read | hypothesis | confirmed if cold reads on the six-member bench, with rows nodes hashed this way, stay within the run-to-run spread of reading in place without hashing; refuted if they move beyond it | open |
| Making a node's hash a hash over its tokens as they are stored (so hashing is reading the tokens) would change every node's identity, which replicas exchange and agree on | fact | blocks are content-addressed by blake3 over their bytes, and sync moves those blocks (`dialog-effects/src/archive.rs`, `Get`/`Put` by digest) | holds; out of scope |
| The tree trusts the provider that makes a node; the provider verifies that what it serves corresponds to its hash | opinion | the maintainer, 2026-11-07, replacing the type-only invariant after hashing a rows node was shown to cost running the encoder on every miss; refined in the next row | refined |
| A node's `hash()` is always the hash of its content: no provider can supply or misstate it. For a node made from rows, asking for it materializes (or streams) the block, once. A consumer that wants to verify compares it with the hash it asked for and pays that cost; one that trusts the provider never asks | opinion | the maintainer, 2026-11-07: "it shouldn't be possible to lie to the persistent node what the hash is ... asking for a hash does mean that you effectively materialize a block, but that would be the cost of it. That way, tree can either trust provider or verify" | - |
| The node cache keys a loaded node by the hash it was asked for, not by calling `hash()` | fact | `NodeCache::get_or_fetch` keeps `(hash, node)` with the requested hash (`dialog-search-tree/src/cache/nodes.rs`) | holds |
| The tree diff (subscriptions, sync) calls `hash()` on nodes it loaded, to compare with the parent's link to them; under a truthful lazy hash every rows node it loads would be encoded and hashed | fact | `dialog-search-tree/src/differential.rs` (comparisons of `link.node` with `node.hash()`, and `seen.contains(node.hash())`) | holds |
| For trusting to stay cheap, tree code must know a node by the hash it requested and call `hash()` only to verify | hypothesis | follows from the two facts above; confirmed by an inventory of `hash()` calls on loaded nodes in non-test tree code, each either replaced by the requested hash or kept as a deliberate verification | open |
| A node read is named by what it was requested by, apart from what it actually is (its hash computed from content), so each consumer chooses to trust or verify | opinion | the maintainer, 2026-11-07: "a thing that you requested by and then a thing to get what it actually is ... different things can decide whether they trust or verify"; possibly as another type | - |
| The memory-only read (`cached`) is used only by writes, to keep an edit surgical: a neighbouring leaf's summary (last key, boundary weights) decides whether an edit can rewrite one leaf without moving a chunk boundary. When the neighbour is not answerable without IO, one site gives up the shortcut and re-chunks (the general path), the other schedules a load and uses it later | fact | `dialog-search-tree/src/tree/transient.rs` on main, the two `accessor.cached(&link.node)` sites (new minimum: `RunVerdict::Widen`; quiet run: `Pending::Fetch`) | holds |
| The memory-only read asks for a value derived from the node (its piece summary, computed and kept on the node), not just the node | fact | `PersistentNode::summary` returns `Option` of a kept summary (`node/persistent.rs`) | holds |
| What the tree needs from it is "answer only if you can without waiting, else none", which names no cache: a provider decides what it can answer at once | hypothesis | confirmed if both sites keep their behaviour when the request is answered by any provider that can answer without IO (a cache, a mapped file); refuted if a site depends on the answer coming from memory specifically | open |
| A node request should be able to say: give me the node; preload it; read it optimistically | opinion | the maintainer, 2026-11-07, the third pending what it is used for | - |
