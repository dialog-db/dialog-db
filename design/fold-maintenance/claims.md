# A folded value is recomputed for its subscriber: claims

| claim | kind | backing | status |
|---|---|---|---|
| a deductive rule can carry a `reduce` clause, evaluated by grouping on the head's other fields, with `count`, `count-distinct`, `sum`, `min`, `max`, `avg` | fact | `notes/aggregation.md`; `rust/dialog-query/src/reduce.rs` `Aggregator` | holds |
| an authored rule with a `reduce` is refused | fact | `rust/dialog-query/src/rule.rs` `open_rule_error`, `TypeError::ReduceInOpenRule` | holds on main at `8ce5f37` |
| keeping a fold current under a subscription was left for later, recomputing on each poll first | fact | `notes/aggregation.md`, Milestones, A5 | holds; whether "recompute" is of one group or of all is not read from the code |
| a subscription of a plain concept answers one changed fact in under a millisecond among 10 rows and among 1000 | fact | dialog-db/dialog-db#773, `rust/dialog-notation/examples/cost.rs`, `cargo run -p dialog-notation --example cost -- 5`, dev profile, medians of 5 | holds on that branch |
| what a reducing rule under a subscription costs as its groups grow | hypothesis | that it grows with the group or with every group. Confirmed or refuted by the same harness with the fold gate lifted, at 10, 100 and 1000 | open; being measured on #773 |
| if a view cannot be lightning fast it will not fly; grouping rows after the query is the last resort | opinion | Irakli, 2026-11-18 | open; no number is set for "lightning fast" |
| the engine may allow a deductive rule to fold, so long as the notation does not let a rule read one | opinion | Irakli, 2026-11-18 | decides the direction of dialog-db/dialog-db#830 |
| folding the changes, with a group's state held in the subscription, keeps a fold current at the cost of the change and with no change of format | hypothesis | the agent's, after DBSP and the counting algorithm. Refuted if a subscription cannot report what stopped holding without reading the group again | open |
| DBSP treats a change as a weighted row and derives the incremental form of a query; CouchDB keeps reductions in the inner nodes of its view B-tree; Noria keeps state only for keys that are read | fact | Budiu and others, "DBSP: Automatic Incremental View Maintenance for Rich Query Languages", VLDB 2023; CouchDB's `couch_btree`; Gjengset and others, "Noria", OSDI 2018 | holds; cited from the papers' abstracts and the agent's recall, not re-read in full for this note |
| keeping a fold current under a subscription is a gap to close | opinion | Irakli, 2026-11-18: "I think we need to close this gap" | decides that this topic is to be built, once its problem is stated and an approach chosen |
| the fold a subscriber holds is the engine's query type over an inner query and a reduce, not a rule (dialog-db/dialog-db#830) | fact | `design/named-fold/journal.md` on `design/named-fold`, the entry of 2026-11-18 | holds as a decision; being built on #773 |
| a fold counts as lightning fast if what one change costs does not grow with the page and stays within 2 times a plain subscription's, on a release build | hypothesis | the agent's proposal for the bar, put to the maintainer 2026-11-18 | open; not answered |
| one poll of a subscription returns a change, the rows that started holding and the rows that stopped, not the whole answer | fact | `Delta { asserted, retracted }`, `dialog-repository/src/repository/branch/subscription.rs` 371-377; [subscriptions-as-built.md](subscriptions-as-built.md) §1 | holds |
| a subscription keeps its whole last answer as a flat list and nothing for a rule, a premise or a group; it learns a row stopped holding only by deriving the touched entity again and comparing | fact | the same file 388-430 and 1309-1330; [subscriptions-as-built.md](subscriptions-as-built.md) §2, §4 | holds; so no signed row of a rule's body exists anywhere today, which the agent's hypothesis of folding the changes needs |
| a reducing rule anywhere in reach makes a subscription ask the whole query again, and a fold is always evaluated over every group, even when one is asked for | fact | `dialog-query/src/concept/query/affected.rs` 338; `concept/query.rs` 1549-1567 ("the body plans and evaluates at empty scope"); the spike's test counts 5 recomputes and 0 maintenances | holds; this is the cost to be measured |
| the one state a subscription keeps across polls beyond its answer is the fixpoint continuation of a recursive concept | fact | [subscriptions-as-built.md](subscriptions-as-built.md) §6, `fixpoint.rs` 1727 | holds; the only precedent for per-subscription operator state |
| on the page, tonk applies a change to a kept copy of every row and then folds, serializes and renders every binding again, so one changed fact costs the rows on the page | fact, read | [tonk-as-built.md](tonk-as-built.md) §2.5, `rust/tonk-display/src/element.rs` 843-883, `fold.rs` 84-145 | holds; not measured in tonk either |
| neither dialog nor tonk's planner aggregates anything today: a count is an element's script over rows, and a list is folded on the page | fact, read | [tonk-as-built.md](tonk-as-built.md) §4 | holds |
| a list of N nested views is N subscriptions of the entity, each checked on every write | fact, read; the count inferred | [tonk-as-built.md](tonk-as-built.md) §6; "a 200-row list opens the same three queries 200 times", `tonk-host/src/stream.rs` 4-9 | holds |
| a folding query's subscription can be a subscription of its inner query with a state for each group beside it, changed by what the inner poll reports, at the cost of the change and with nothing new asked of the engine's maintenance or of storage | hypothesis | the agent's, in [direction.md](direction.md), with what confirms and refutes it. It replaces the earlier wording, which feared no signed rows existed: they exist at a subscription's edge | open; to be tested once the folding query is built on #773 |
