# Claims

| claim | kind | backing | status |
|---|---|---|---|
| A fact key is a tag byte, then its components: EAV is entity, attribute, value slot; AEV is attribute, entity, value slot; VAE is value slot, attribute, entity; history and coverage are a raw fixed-width version, entity, attribute, value slot. Entity and attribute are `0x00`-escaped, `0x00`-terminated. | fact | `build_key` and `parse_key_layout` in `rust/dialog-corpus/src/key/varkey.rs` at `7e9f621` | holds |
| The value slot is one type byte and the value's order-preserving encoding. A spilled value's slot holds the encoding of its first raw bytes, and a sentinel byte plus a 32-byte hash end the key. A key is spilled exactly when 33 bytes, starting with the sentinel, remain after the final component. | fact | `ValuePayload`, `SPILL_TAIL_LENGTH`, `parse_key_layout` in `varkey.rs` | holds |
| How far a value's encoding runs is decided by its type byte alone: 16 bytes for the 128-bit integers (4, 5), 8 for a float (6), 1 for a boolean (2), dialog-number's self-delimiting encoding for the number band (9), escaped-terminated for bytes, entity, text, record, symbol (0, 1, 3, 7, 8) and for a composite (22). Any other byte makes the key unparseable. | fact | `value_payload_len` and `delimited_as` in `varkey.rs` | holds |
| The type bytes in use mix framing classes: fixed-width (2, 4, 5, 6), escaped-terminated (0, 1, 3, 7, 8, 22) and self-delimiting (9) interleave, so no range of tag values today names one class. | fact | the row above | holds |
| The type byte sorts first within a value slot, so the bands of an attribute's values sort by tag value; within a band they sort by the encoding. In VAE the type byte is the key's second byte. | fact | `build_key` in `varkey.rs` | holds |
| In VAE the value slot is followed by the attribute and entity, so a reader must know where the value ends to read anything after it. In EAV, AEV, history and coverage the value is the last component, but its end must still be known to tell a spill tail from value bytes. | fact | `parse_key_layout` in `varkey.rs` | holds |
| A release that meets an unknown type byte fails a scan over the key (`InvalidKey`; structural key corruption is loud by design), and on main a cardinality-one write to its cell fails too. #884 makes that write pass the claim over and leave it in place; reads still fail. | fact | `reconstruct` in `rust/dialog-corpus/src/tree.rs`; `a_cardinality_one_write_passes_over_a_claim_of_a_type_it_does_not_know` on #884 | holds |
| A pull whose delta carries a covering history record (one that supersedes or retracts) with an unknown type byte fails on the receiver: the history screen parses the record's key to find the cell to retire. | fact | `coverage_range` and `screen_record` in `rust/dialog-corpus/src/merge.rs` | holds; not yet shown by a test |
| A pull whose delta carries only a data entry with an unknown type byte integrates it: the data screen reads the datum's versions and never parses the key. | hypothesis | confirmed by a two-replica test that plants such an entry on one side and pulls; refuted if the pull fails | open |
| An escaped-terminated encoding of any byte string keeps bytewise order, so a type whose order is its bytes' order loses nothing by being framed that way. | fact | `encode_bytes` in `rust/dialog-corpus` (the ordkey escape of `0x00` as `0x00 0xFF`) and the text, bytes and composite bands that use it | holds |
| A fixed-width value framed by its tag needs only its width to be stepped over; the width can be a function of the tag value. | fact | follows from the slot layout: nothing but the width is read to step over 2, 4, 5 and 6 today | holds |
| A self-delimiting encoding (the number band) cannot be stepped over by a release that does not know the codec, so it cannot be a framing class an unknown type uses. | fact | `dialog_number::encoded_len` is the only way the band's end is found | holds |
| The ValueDataType discriminants 23, 24 and 25 (map, record, list) never appear as a key's type byte: keys fold them into the composite band, 22. | hypothesis | `ValueDataType::band` maps map and list to composite and `delimited_as` accepts only 22, so a key with 23 to 25 would not parse; confirmed by a scan of a fixture's keys for those bytes | open |
| A rewrite of every fact key is not part of the stored-format migration #857 plans: that migration rewrites rules and concepts. | fact | `design/stored-format.md` and `design/stored-format/plan.md` on `design/stored-format` (`e0e6728`) | holds |

| Framing by tag range costs no byte and leaves the order of every existing band unchanged, provided only tags not yet assigned get a range. | hypothesis | follows from the rows above; confirmed by a property test that builds keys for an unknown tag of each class and parses them on a release that knows only the ranges | open |
