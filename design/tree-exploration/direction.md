# How a consumer that can only query explores a branch's search tree

Decision: what the query engine offers for exploring a search tree, for:
a consumer that can only query cannot draw a branch's search tree in a
number of reads that does not grow with the tree, so the one embedder
that shows it reads blocks through machinery of its own.

**Column 6 is struck by the maintainer, 2026-11-13:** a node's contents
are read through resolvers; commands exist so that a query which would
fetch a block is not issued. Column 7 was born from looking at what was
left: columns 2 to 5 all put a rule and a concept between the consumer
and the resolver, and every difficulty recorded in them comes from that
layer, not from the resolvers.

Not decided. Columns 4 and 5 were on the table before the problem was
stated and were kept out until now. Column 6 was born from the decision
on what is held ([design-held](design-held.md)), which the maintainer
settled as commands whose built-in handlers assert into the overlay; it
asks whether the rest of the tree can be reached the same way. Use cases
are numbered as in [use-cases](use-cases.md).
