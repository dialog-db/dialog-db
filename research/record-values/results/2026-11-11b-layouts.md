## The layouts

The same canonical content (fields sorted by name and value, repeats
dropped) written three ways:

```
inline     geo/lat 00 09 ‹37.77›  geo/lon 00 09 ‹-122.42›  00

header     02 │ geo/lat 00 geo/lon 00 │ 01 09 ‹37.77›  02 09 ‹-122.42›  00
           count  every name once,       a field names its attribute by
                  sorted                 index (from 1; 0 ends the fields)

encounter  geo/lat 00 09 ‹37.77›  geo/lon 00 09 ‹-122.42›  00
           a name at its first use; every later use 01 ‹index in order of
           first use›; for this record, the same bytes as inline
```

A nested record's fields name attributes in the table of the record it sits
in, so in the header and encounter layouts a nested record is not a record
on its own. Taking one out (binding `?e` in `{tonk.view/event: ?e}` to a
value of its own) writes it again with its own names.

A trailer (encounter plus, at the end, an index of where each top-level name
is first used) is estimated, not built.

| tonk view bindings | 5,674 | 1.89 | **1.02** | 1.05 | 1.06 |

A table pays where a record nests a set and the nested records repeat names
(tonk's bindings); a flat record has nothing to share (revision records with
versions as bytes).

## Finding a field, and taking nested records out

ns a record, seven rounds interleaved. "Finding" returns the field's value
slots without decoding them; "taking out" makes each of a view's events a
record of its own (in the inline layout, a copy of its bytes).

| read | layout | min | median | max |
|---|---|--:|--:|--:|
| a revision's issuer (fourth of seven names) | inline | 130 | 138 | 197 |
| | header | 211 | 229 | 301 |
| | encounter | 257 | 286 | 330 |
| a revision's skips (the last name) | inline | 229 | 253 | 276 |
| | header | 158 | 172 | 183 |
| | encounter | 245 | 268 | 366 |
| a view's events, each a record of its own | inline | 387 | 433 | 549 |
| | header | 2,824 | 3,054 | 4,785 |
| | encounter | 2,319 | 2,570 | 2,681 |

- Finding a field costs about the same in every layout, within about 100 ns
  a record. The header reads its table first, so an early field is slower
  and a late one faster.
- The encounter layout learns names as it walks, so it cannot skip a nested
  record without reading it: a back-link after it may name a name first used
  inside it.
- Taking nested records out costs 6 to 7 times the inline copy in both table
  layouts, the price of nested records that are not records on their own.

## Not measured

- A nested record bound as a view into its outer record (the outer bytes and
  a span, read through the outer table), which would make taking one out
  free until it is stored or compared with a record from elsewhere.
- The trailer, built.
- Sharing names across records (a stream's or a node's table); see the
  [design](../design.md#2-attribute-names-on-the-wire).
