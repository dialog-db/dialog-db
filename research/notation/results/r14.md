````text
You are using a notation for a database language. Work from the text below alone. Do not use any tools other than the one Read you were told to make, and do not search files or the web.

Basics you can rely on:
- The database stores facts: entity, attribute, value. Entities are URIs like `bug:01`.
- `(name arg label: value ...)` is a call. Every definition has exactly one primary parameter, written without a label; every other parameter has a label. At a call, the primary may be written bare or as `of:`, in any position.
- `?x` is a variable. A call with variables is a question; it returns every match.
- A call whose name ends in `!` writes facts. Many devices write to the same database and sync with each other.
- `{a 1 b 2}` is a map, `[a b]` a vector, `:x` a keyword. A vector of keywords such as `[:todo :done]` as a type means "one of these values".
- `(concept (name params...) body...)` defines a concept: the body says which facts make one up. Reading the concept matches those facts; writing it stores them.
- `(xyz.bug/title ?b is: ?t as: :text pick: :last)` is the fact (?b, xyz.bug/title, ?t), whose value is text; when several values exist, the last one written counts.
- Writing a concept without its primary creates the entity. If the definition says what the primary is derived from, the entity is derived from those values, so the same values give the same entity on every device. Writing with the primary given changes that existing entity.

The definition:
```
(concept (bug {title author} ?b title: ?t author: ?a status: ?s)
  (xyz.bug/title ?b is: ?t as: :text)
  (xyz.bug/author ?b is: ?a as: :text)
  (xyz.bug/status ?b is: ?s as: [:todo :done] pick: :last))
```

Task A. Save these rows as new bugs:

| title         | author | status |
|---------------|--------|--------|
| Crash on save | ada    | :todo  |
| Slow search   | ada    | :todo  |
| Bad font      | bob    | :todo  |

Task B. A teammate tells you that the "Slow search" bug is the entity `bug:7f3a`. Change that bug's status to :done.

Task C. Later, on a different device that has not synced yet, this row arrives with no entity. Save it:

| title         | author | status |
|---------------|--------|--------|
| Crash on save | ada    | :done  |

Task D. Find every bug whose author is ada, with its entity and status.

Answer:
1. The exact calls you write for Task A.
2. The exact call you write for Task B.
3. The exact call you write for Task C.
4. The exact query you write for Task D.
5. Once the devices have synced, how many bugs titled "Crash on save" exist, and what is the status of each? Confidence low/medium/high.
6. What does the part of the definition next to `?b` mean, and how did it affect your calls?
7. Rate how clear the notation was, 1 (baffling) to 5 (obvious), name the one thing that confused you most, and say concretely what spelling would have made it obvious.
````
