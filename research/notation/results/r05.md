<details><summary><code>K1 #hash head</code> (sha256 <code>0ddcd8c24a3d79e8</code>)</summary>

````text
You are reading a sketch of a notation for a database language. Answer from the text below alone. Do not use any tools, do not search files or the web.

Basics you can rely on:
- The database stores facts: entity, attribute, value. Entities are URIs like `user:01`.
- `(name first label: value ...)` is a call: the first argument is positional, every other argument is labeled.
- `?x` is a variable. A call with variables is a question; it returns every match.
- A call whose name ends in `!` writes facts.
- `{a 1 b 2}` is a map, `[a b]` a vector, `:x` a keyword.
- `(concept (name params...) body...)` defines a concept: the body says which facts make one up. Reading the concept matches those facts; writing it stores them.
- `(rule head premises...)`: whenever the premises match, the head holds. `(define (name params...) body)` defines a function.
- `(xyz.user/email ?u is: ?e as: :text)` is the fact (?u, xyz.user/email, ?e), whose value is text.

The definition:

```
(concept (user (?user #hash [:email :name]) email: ?e name: ?n)
  (xyz.user/email ?user is: ?e as: :text)
  (xyz.user/name ?user is: ?n as: :text))
```

Questions (answer each in 1-3 sentences, plus confidence low/medium/high):
1. `(user! email: "a@x.org" name: "Ada")` gives no entity. Which entity are the facts stored on? Could you predict its id from the values?

3. Also `(user! user:01 email: "b@x.org" name: "Bob")` was run. Which users does `(user ?u email: ?e name: ?n)` return?
4. Later `(user! email: "a@x.org" name: "Ada L.")` runs. Does it update the existing Ada or create a different user? Why?
5. Write a call that creates a user with email "c@x.org" and name "Cy", letting the system choose the entity.
````
