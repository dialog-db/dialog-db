# R01: does a definition say a write without an entity derives one?

2026-11-04 (UTC). 15 readers, 5 variants; model `haiku`, agent type `general-purpose`. Every answer, unedited, is in [`r01.jsonl`](r01.jsonl); the tally scores each reader's first answer.

## Tally

Recounted from the answers. A reader counts when it says a write that leaves the entity out lands on an entity derived from the values, so rerunning it leaves one bug.

| variant | spelling | derived, one bug |
|---|---|---|
| A | `(default ?bug is: {…})`, the spec as it stood | 0/3 |
| B | `(identity ?bug from: {…})` | 3/3 |
| C | a second `bug` concept passing a record in the entity slot | 0/3 |
| D | `(?bug or: {…})` in the head | 1/3, two more hedged |
| E | `(option ?bug from: {…})` in the head | 0/3 |

## Notes

Every reader that saw a derivation also said a status change makes a new bug, because status is in the hashed record. Readers were then told the intent and asked what spelling would have shown it; those second answers are in `after_follow_up` and are not scored. Most proposed writing `hash` in the line.

````text
You are reading a sketch of a notation for a database language. Answer from the text below alone. Do not use any tools, do not search files or the web.

Basics you can rely on:
- The database stores facts: entity, attribute, value. Entities are URIs like `bug:01`.
- `(name first label: value ...)` is a call: the first argument is positional, every other argument is labeled.
- `?x` is a variable. A call with variables is a question; it returns every match.
- A call whose name ends in `!` writes facts.
- `{a 1 b 2}` is a map.
- `(concept (name params...) body...)` defines a concept: the body says which facts make one up. Reading the concept matches those facts; writing it stores them.
- `(xyz.tonk.issue/title ?bug is: ?t as: :text)` is the fact (?bug, xyz.tonk.issue/title, ?t), whose value is text.

The definition:

```
(concept (bug ?bug title: ?t status: ?s)
  (default ?bug is: {xyz.tonk.issue/title ?t xyz.tonk.issue/status ?s})
  (xyz.tonk.issue/title ?bug is: ?t as: :text)
  (xyz.tonk.issue/status ?bug is: ?s as: :text))
```

Questions (answer each in 1-3 sentences, plus confidence low/medium/high):
1. `(bug! title: "typo" status: "todo")` gives no entity. Which entity are the facts stored on? Could you predict its id from the values?
2. That same write runs again tomorrow in another session. How many bugs titled "typo" exist afterwards?
3. Also `(bug! bug:01 title: "crash" status: "todo")` was run. Which bugs does the question `(bug ?b title: ?t status: ?s)` return?
4. Later someone runs `(bug! title: "typo" status: "done")`. Does that update the existing "typo" bug or create a different one? Why?
5. Write a call that creates a bug titled "slow" with status "todo", letting the system choose the entity.
6. Is the entity parameter required, optional, or something else? Answer separately for writes and for questions.
7. Rate how clear the definition was, 1 (baffling) to 5 (obvious), and name the one thing that confused you most.

Reply with numbered answers only.
````
