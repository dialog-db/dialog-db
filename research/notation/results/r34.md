For a rate in this middle range, the rounds need more readers per variant. Twenty or thirty would separate 50 percent from 70.

## Why the other half misses

The misses are no longer about storage. Readers on both spellings now say the note needs `xyz.tonk.post/content` and that a rule could supply it. They split on how rules are evaluated:

- **Goal-directed (the misses).** A rule is reached only through its head's name: "the `memo` rule only runs if something asks for `memo`, and the query asks for `note`". Another reader: "the query never asks for `memo`, so the rule is never reached". This is Prolog's and top-down Datalog's model.
- **Data-driven (the hits).** A rule's conclusion holds whether or not its head is asked for, and so gives its attributes values. Even so, the hits mostly hedged: "if rule heads don't materialize attributes, the query would return nothing".

Several of the misses spelled out the other model themselves, then chose against it because nothing in the code said which applies: "if the engine applied rules forward, the rule would derive `xyz.tonk.post content: "hello world"` for `mail:one`, and the query would return it".

## What follows

What is left is one fact readers cannot see in the code: a rule reaches every read of the attributes its conclusion covers, not only reads of its concept's name. That is a statement about evaluation, and the obvious test is to state it.

The next round should put one sentence, on the derive case, over two bases:

- the plain domain form (R32, 0 of 20 so far);
- the one-attribute building blocks (14 of 30).

The sentence: a rule's conclusion gives values to the attributes behind its concept whether or not anything asks for that concept, and every read of those attributes sees them. Run 20 readers per variant.
