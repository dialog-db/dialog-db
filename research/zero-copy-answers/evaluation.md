# Zero-copy answers: evaluation

The axes the decision turns on. Every axis compares the same store, seeded
from the same seed, built once per run in the same binary; the variants
are the binding mode (`DIALOG_LAZY_BINDINGS`) and the encoding (tonk's
JSON or the frame).

## Datasets

Generated by the harness from fixed seeds, nothing on disk:

- **stuff**: `dialog-perf`'s population, two text fields (`stuff/name`,
  `stuff/role`), short entities (`id:stuff-N`), at 2,000 and 20,000
  rows.
- **issue**: tonk's issue list shape (`v2/issue`): eight fields, `ident`,
  `title` (five words), `status` (one of four), `priority` (natural),
  `created` (natural), `creator` and `assignee` (one of 20 people),
  `project` (one of 8), every entity a 56-byte `did:key` URI as tonk's
  are. 300 rows is the size of tonk-team's issue list
  (`research/single-file-format/evaluation.md`), 3,000 its 10×.

The delta: every 20th row's `role` (stuff) or `status` (issue) moves on
by one value, one commit, the rows of those entities before and after.

## Axes

### 1. Engine: query to conclusions

- **Workload:** a concept query over every field, all entities, warm
  (one warm-up run first).
- **Reports:** instructions (callgrind, inclusive of
  `answers_phase_engine`), allocation calls and bytes (counting
  allocator), wall time.
- **Harness:** `rust/dialog-perf/src/bin/answers.rs`, phase `engine`.
- **Status:** run, see the journal.

### 2. Wire: conclusions to bytes

- **Workload:** the conclusions of axis 1, as tonk's snapshot frame
  (`project` + `serde_json`), and as a `dialog-answer` frame read from
  `ConceptConclusion::view`.
- **Reports:** instructions, allocations, wall time, bytes.
- **Harness:** phases `json_encode`, `frame_encode`.
- **Status:** run.

### 3. Receiver: bytes to something the page can read

- **Workload:** natively, `serde_json` back into tonk's `Conclusion`s,
  against accepting the frame and reading every cell, or two fields of
  every row. In Chromium, `JSON.parse` of the same bytes and reading two
  fields, against the JS frame reader reading two fields or all of them.
  The page today also runs `serde_wasm_bindgen` over the parsed object
  graph back into Rust structs; neither side counts it, so the JSON side
  is flattered.
- **Reports:** instructions and allocations natively, wall time in both.
- **Harness:** phases `json_decode`, `frame_read_all`, `frame_read_two`;
  `research/zero-copy-answers/bench/` for Chromium.
- **Status:** run.

### 4. Deltas

- **Workload:** the delta above, encoded both ways, the frame on the
  session that sent the snapshot.
- **Reports:** bytes.
- **Status:** run.

### 5. Correctness

- Every `dialog-query` (976) and `dialog-repository` (713) test, with
  lazy bindings on, and `dialog-query`'s with them off.
- Every run checks that the frame holds what the JSON holds, every row,
  every field (`check_same`), and refuses to report one that does not.
- **Status:** passing.
